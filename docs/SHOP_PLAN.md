# 워프 비컨 상점 기획서

협곡(`canyon`)을 통과하고 궤도(`orbit`)에 진입하기 직전에 한 번 열리는 상점입니다. 목표는 지금은 쌓이기만 하는 **회수품(◆ salvage)** 에 쓸모를 주고, 루프마다 다른 빌드를 골라 다시 도전할 이유를 만드는 것입니다.

> 이 문서는 기획만 다룹니다. 수치는 현재 코드(`src/game.ts`)와 seed=1 자동 조종 1회 클리어 결과를 기준으로 잡은 초안이며, 구현 후 플레이테스트로 조정합니다.

---

## 1. 설계 원칙

1. **선택이 있어야 한다**: 1루프 평균 수입으로는 5개 항목 중 **2개 정도만** 살 수 있게 가격을 정합니다. 전부 살 수 있으면 상점이 아니라 보너스입니다.
2. **보스전 직전이라는 위치를 살린다**: 수리와 폭탄처럼 "지금 당장 살아남기" 항목과, 장갑·무기·부스트처럼 "이번 런 전체에 투자하기" 항목이 서로 경쟁하게 합니다.
3. **잘한 플레이에 보상한다**: 피격이 적은 플레이어가 회수품을 더 많이 남깁니다. 기존 등급 보너스(S 500 / A 300 / B 150 / C 50)는 다음 루프 상점 예산이 됩니다.
4. **상태는 순수하게 유지한다**: 상점도 `stepGame()` 안의 결정론적 상태 전이로 처리합니다. DOM은 결과를 그리기만 합니다.

## 2. 회수품 수입 (현재 코드 기준)

| 획득원 | 회수품 | 위치 |
| :--- | ---: | :--- |
| 드론 / 보급기 격추 | +10 | `src/game.ts` 엔티티 정리 루프 |
| 중계탑 1기 파괴 | +50 (4기 = 200) | 같은 위치, `pylon` |
| 스테이지 클리어 등급 보너스 | S 500 / A 300 / B 150 / C 50 | 보스 처치 시 |

seed=1 자동 조종 1루프에서 실제로 측정한 누적 값입니다.

| 시점 | 누적 회수품 |
| :--- | ---: |
| 접근로 종료 (50초) | 약 190 |
| 환초 종료 | 약 410 |
| **협곡 종료 = 상점 진입** | **약 450** |
| 클리어 (등급 B 보너스 포함) | 660 |

**1루프 상점 예산 기준**: 보통 플레이 약 450, 서툰 플레이 약 250~300, 잘한 플레이 약 500~550. 2루프부터는 1루프에서 남긴 돈과 등급 보너스가 더해져 예산이 약 400~800이 됩니다.

> 수입 변경은 이 문서 범위 밖입니다. 적 로스터가 추가되면(다음 기획 2번) 수입이 늘어나므로, 그때 2절 표를 다시 측정해 가격을 조정합니다.

## 3. 구매 항목과 가격

| # | 항목 (표시명) | 효과 | 기본 가격 | 한도 | 종류 |
| :-- | :--- | :--- | ---: | :--- | :--- |
| 1 | **긴급 수리** | 장갑(`hull`)을 `maxHull`까지 회복 | 80 | 상점 1회당 1번 | 소모 |
| 2 | **폭탄 보급** | `bombs +1` | 100 | 상점 1회당 2번, 최대 5개 | 소모 |
| 3 | **장갑 증설** | `maxHull +2`, `hull +2` | 220 | 런 전체 2단계 (8 → 10 → 12) | 영구 |
| 4 | **트윈 안정기** | 피격해도 무기가 2단계 아래로 떨어지지 않음. 구매 즉시 1단계면 2단계로 올림 | 280 | 런 전체 1단계 | 영구 |
| 5 | **부스트 탱크** | 부스트 지속 2초 → 3초 (소모율 0.5/s → 0.33/s) | 160 | 런 전체 1단계 | 영구 |
| — | **출격** | 상점을 닫고 궤도로 진입 | 무료 | — | — |

### 가격 규칙
- **영구 항목은 단계마다 비싸짐**: 장갑 증설 2단계는 `220 × 1.5 = 330`.
- **루프 보정**: 모든 가격에 `× (1 + 0.15 × (loop − 1))`를 곱하고 10 단위로 반올림합니다 (루프 2: ×1.15, 루프 3: ×1.3). 상한은 ×1.6입니다. 적 속도 보정 `loopSpeed`와 같은 방향으로 올리되 더 완만하게 올립니다.
- 잔액이 부족한 항목은 비활성으로 보이고, 부족한 금액을 표시합니다 (`◆ 40 부족`).

### 예산별 구매 예시 (1루프)
| 예산 | 대표 선택 | 남는 금액 |
| ---: | :--- | ---: |
| 250 (서툰 플레이) | 수리 + 폭탄 1개 | 70 |
| 450 (보통) | 장갑 증설 + 부스트 탱크 | 70 |
| 450 (보통, 대안) | 트윈 안정기 + 수리 | 90 |
| 550 (잘한 플레이) | 트윈 안정기 + 장갑 증설 | 50 |

모든 예산 구간에서 "살아남기"와 "투자" 중 하나를 골라야 하는지 확인했습니다. 1루프 450으로는 영구 항목 3개(660)를 모두 살 수 없으므로, 영구 업그레이드를 다 갖추려면 2~3루프가 걸립니다.

## 4. 루프 간 유지 규칙

`nextLoop()`는 지금 `score`, `salvage`, `lives`만 다음 루프로 넘깁니다. 상점이 생기면 다음 규칙을 적용합니다.

| 항목 | 다음 루프(`nextLoop`) | 처음부터(`restartGame`) / 게임 오버 |
| :--- | :--- | :--- |
| 회수품 | **유지** (남은 금액 + 등급 보너스) | 0 |
| 영구 업그레이드 (장갑 증설, 트윈 안정기, 부스트 탱크) | **유지** | 초기화 |
| `maxHull` | 업그레이드 단계로 다시 계산 (8 + 2×단계) | 8 |
| `hull` | `maxHull`로 가득 참 | 8 |
| 폭탄 | 루프 시작 시 3개로 초기화 (산 폭탄은 이월되지 않음) | 3 |
| 무기 단계 | 1단계에서 시작, 트윈 안정기가 있으면 2단계 | 1 |
| 상점 내 1회 한도 (수리, 폭탄) | 상점을 열 때마다 초기화 | — |

- 소모 항목은 이월하지 않습니다. 그래야 "보스전 직전에 돈을 쓰는" 결정이 매 루프 다시 생깁니다.
- 영구 항목을 유지하면 루프가 빨라져도(+20%/루프) 따라갈 수 있다는 성장감이 생깁니다.
- 하이스코어 저장(다음 기획 4번)이 생기면, 상점 구매 여부는 점수 기록에 영향을 주지 않습니다.

## 5. 게임 흐름

```
canyon: 방폭문 3/3 개방
  → transition 1.5초 (기존 연출 유지)
  → phase 'shop'  ← 시뮬레이션 정지, 피격 없음, 배경은 우주 진입 연출로 천천히 스크롤
  → [출격]
  → transition → orbit 진입 (기존 enterSegment)
```

- 상점은 **루프마다 1번, 협곡 뒤에서만** 열립니다.
- 상점이 열리면 무전 한 줄을 띄웁니다: GALE "워프 비컨 점등. 회수품으로 정비하고 가." (`dialogue.shopArrival`)
- 상점에는 시간 제한이 없습니다. 일시정지(`P`)는 상점에서 동작하지 않습니다. 상점이 이미 정지 화면이기 때문입니다.
- 출격하면 궤도 진입 시 기존처럼 `invulnTimer`가 적용됩니다.

## 6. UI 흐름

기존 메뉴 카드(`#game-overlay` / `.game-card`)를 재사용하고, 카드 안에 항목 목록만 새로 넣습니다. 타이틀·일시정지·결과 화면과 같은 디자인을 씁니다.

### 공통 레이아웃
```
+--------------------------------------+
| 워프 비컨 // 정비소          ◆ 450   |  kicker + 현재 잔액
| 궤도 진입 전 정비                     |  title
|--------------------------------------|
| [1] 긴급 수리      장갑 ▮▮▮▮▯▯▯▯→가득   80 |
| [2] 폭탄 보급      ◆◆◆ → ◆◆◆◆        100 |
| [3] 장갑 증설      8 → 10             220 |
| [4] 트윈 안정기    무기 2단 보장       280 |  ← 부족: "◆ 30 부족"(비활성)
| [5] 부스트 탱크    2초 → 3초          160 |
|--------------------------------------|
|        [ 출격 ]                       |  primary
| 1–5 구매 · Enter 출격                  |  hint
+--------------------------------------+
```
- 각 줄에는 **현재 → 구매 후** 값을 보여줍니다. 수치를 몰라도 무엇이 바뀌는지 알 수 있어야 합니다.
- 구매하면 잔액 숫자가 깜빡이고, 해당 줄에 `+` 효과를 0.3초 동안 보여줍니다. 한도에 도달한 줄은 `완료` / `최대`로 표시합니다.
- 상단 HUD(장갑, 폭탄, 회수품)는 카드 뒤에서도 즉시 갱신되어, 구매 결과를 HUD에서도 확인할 수 있습니다.
- 실수 방지: 구매는 바로 확정합니다(되돌리기 없음). 대신 출격은 실수로 누르기 어렵게, 항목 목록 아래에 떨어뜨려 배치합니다.

### 데스크톱 (키보드 / 마우스 / 게임패드)
| 입력 | 동작 |
| :--- | :--- |
| `1`–`5` | 해당 항목 구매 |
| `↑`/`↓` 또는 `W`/`S` | 항목 포커스 이동 (포커스 링 표시) |
| `Space` / `J` / `Z` | 포커스된 항목 구매 |
| `Enter` | 출격 (포커스가 어디 있든) |
| 마우스 클릭 | 항목 줄 또는 출격 버튼 |
| 게임패드 | 십자키 이동, `A` 구매, `Start` 출격 |

- 상점이 열리면 첫 포커스는 **출격이 아닌 1번 항목**에 둡니다. 보스 직전에 Enter를 연타하다 상점을 건너뛰지 않게 하려는 것입니다. 다만 Enter는 항상 출격이므로, 상점을 원하지 않는 숙련자도 한 번에 넘어갈 수 있습니다.
- 사격 키를 누른 채 상점에 들어오면 키를 한 번 뗄 때까지 구매 입력을 무시합니다(의도치 않은 연속 구매 방지).

### 모바일 (터치)
- 상점이 열리면 기존 규칙대로 터치 조작(스틱, FIRE/BOOST/BOMB/VIEW)과 일시정지 버튼을 숨깁니다(`updateMenu()`의 `show` 분기).
- **세로(390×844 기준)**: 항목을 한 줄에 하나씩 세로로 배치합니다. 각 줄 높이는 최소 52px(터치 목표 44px 이상)이고, 출격 버튼은 카드 하단에 전체 너비로 둡니다. 카드 높이가 화면을 넘으면 항목 목록만 스크롤하고 출격 버튼은 고정합니다.
- **가로(844×390 기준)**: 항목을 2열 그리드(3+2)로 배치하고, 출격 버튼은 오른쪽 아래에 둡니다.
- 안전 영역(`safe-area-inset`)은 기존 메뉴 카드 레이아웃 규칙을 그대로 따릅니다.
- 탭 한 번으로 구매합니다. 비활성 항목을 탭하면 부족 금액 표시를 흔들어서 알려줍니다.
- 키 안내(`1–5 구매 · Enter 출격`)는 터치 모드에서 숨깁니다.

### 언어
모든 문구는 `src/i18n.ts`의 `en` / `ko`에 키를 추가합니다. 예: `shop.kicker`, `shop.title`, `shop.item.repair`, `shop.item.repair.desc`, `shop.short` (`◆ {n} 부족`), `shop.maxed`, `shop.launch`, `shop.hint`, `dialogue.shopArrival`. 새 한글 글자가 생기면 README 절차대로 Galmuri11 서브셋을 다시 생성합니다.

## 7. 기존 상태·코드와의 연결

### 상태 (`src/game.ts`)
```ts
export type GamePhase = 'title' | 'playing' | 'transition' | 'shop' | 'win' | 'game_over';
export type ShopItem = 'repair' | 'bomb' | 'armor' | 'twin' | 'tank';
export type SegmentDef = { /* 기존 필드 */ shopAfter?: boolean };      // canyon에만 true
export type GameInput = { /* 기존 필드 */ shop?: ShopItem | 'launch' };

// GameState 추가 필드
upgrades: { armor: 0 | 1 | 2; twin: 0 | 1; tank: 0 | 1 };  // 런 유지
shopBuys: { repair: number; bomb: number };                // 상점 열 때마다 0
```

### 전이
- `transition()` 끝(`transitionT >= 1`)에서, 방금 끝난 구간의 `shopAfter`가 true이고 이번 루프에 아직 상점을 열지 않았다면 `enterSegment` 대신 `phase = 'shop'`으로 바꿉니다. 이때 `shopBuys`를 초기화하고 `dialogue.shopArrival`을 띄웁니다.
- `stepGame()`의 `phase === 'shop'` 분기에서는 `input.shop`만 처리합니다. 구매하면 가격을 확인하고, `salvage`를 차감하고, 효과를 적용합니다. `'launch'`면 `enterSegment(s, 'orbit', ground)`로 진입합니다. 적, 탄, 타이머는 진행하지 않습니다.
- 가격 계산은 `shopPrice(item, s)`라는 순수 함수로 export합니다(테스트와 UI가 같은 값을 쓰게 하기 위함).

### 효과가 닿는 기존 코드
| 효과 | 기존 위치 | 변경 |
| :--- | :--- | :--- |
| 장갑 증설 | `maxHull`(이미 상태에 있음), 리스폰 시 `hull = maxHull` | `maxHull = 8 + 2 × upgrades.armor` |
| 트윈 안정기 | `damage()`의 `weaponLv = max(1, weaponLv − 1)` | 하한을 `upgrades.twin ? 2 : 1`로 변경 |
| 부스트 탱크 | `bst` 소모 `control.boost ? -0.5 : 0.35` | 소모율을 `upgrades.tank ? 0.33 : 0.5`로 변경 |
| 폭탄 / 수리 | `bombs`, `hull` | 직접 증가, 한도는 가격 함수에서 검사 |
| 루프 유지 | `nextLoop()` | `upgrades` 복사 후 `maxHull`, 시작 `weaponLv` 다시 계산 |

### 화면 (`src/main.ts`, `index.html`, `src/style.css`)
- `updateMenu()`: `menu === 'shop'`을 `show` 대상에 넣습니다. 카드의 kicker, title, copy, hint를 `shop.*` 키로 채우고, 새 `#shop-list` 컨테이너를 보여줍니다(다른 메뉴에서는 숨김). `#primary-action`은 `shop.launch`를 씁니다.
- `#hull-bars`는 이미 `maxHull` 길이로 그리므로 10~12칸도 그대로 표시됩니다. 좁은 세로 화면에서 줄바꿈이 생기지 않는지만 확인하면 됩니다.
- 키 입력: 기존 `pendingPause`/`pendingBomb` 방식처럼 `pendingShop`을 하나 두고 다음 틱의 `GameInput.shop`으로 넘깁니다.
- `window.__game`에 `upgrades`, `shopBuys`, `shopPrices`를 추가합니다.

### 테스트 훅 & 자동 조종
- `?segment=shop`: 협곡을 클리어한 상태(회수품 450, 장갑 4/8, 폭탄 3)로 상점을 바로 엽니다. 스크린샷과 밸런스 확인용입니다.
- `?salvage=N`: 시작 회수품을 덮어씁니다(가격 구간 테스트용).
- 자동 조종 상점 규칙(결정론): 장갑이 절반 이하면 수리를 사고, 그다음 트윈 → 장갑 → 탱크 → 폭탄 순으로 살 수 있는 것을 산 뒤 출격합니다. 그러면 기존의 자동 조종 전체 클리어 테스트가 계속 통과합니다.

### 단위 테스트 (`tests/game.test.mjs`)
- 협곡 클리어 → `phase === 'shop'` → `'launch'` → `segment === 'orbit'`
- 잔액이 부족하면 구매되지 않고, 구매하면 `shopPrice`만큼 정확히 차감됨
- 한도: 수리 1회, 폭탄 2회 / 최대 5개, 장갑 2단계, 트윈·탱크 1단계
- 트윈 안정기를 산 뒤 피격하면 `weaponLv >= 2`
- 부스트 탱크를 산 뒤 `bst` 1 → 0까지 약 3초
- `nextLoop`는 `upgrades`와 `salvage`를 유지하고, `restartGame`은 둘 다 초기화
- 루프 2 가격 = 기본 가격 × 1.15를 10 단위로 반올림

## 8. 범위 밖 / 후속

- 상점 NPC 초상화, 구매 효과음 → 사운드 패스(다음 기획 5번)
- 미사일(`MSL`), 옵션 윙팟 같은 신규 무기 → 적 로스터가 확장된 뒤 상점 항목으로 검토
- 무작위 진열·할인 → 결정론과 비교 가능성을 해치므로 보류
- 회수품 수입 재조정 → 적 로스터 확장 후 2절을 다시 측정

## 9. 성공 기준 (플레이테스트)

- 1루프 보통 플레이(약 450)에서 영구 항목은 최대 2개까지만 살 수 있고, 플레이어가 무엇을 포기할지 고민하게 된다.
- 테스터 3명 중 2명 이상이 루프마다 다른 조합을 고른다.
- 상점 화면에 머무는 시간의 중앙값이 15초 이하다(흐름을 끊지 않는다).
- 터치 세로·가로 모두에서 오탭으로 출격하는 일이 없다.
